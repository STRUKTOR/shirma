# Ширма — обезличивание документов для работы с Claude Code

## 1. Цель

Сотрудники работают с документами через Claude Code (с ноутбука, с телефона — через Remote Control сессии на ноутбуке). Документы содержат персональные данные и реквизиты. Инструмент заменяет их на реалистичные фейки до того, как Claude их увидит, и делает обратную замену в результатах.

Принятые ограничения:
- всё локально на ноутбуке, без LLM и без сети;
- macOS и Windows;
- языки: русский и казахский;
- форматы: txt, md, csv, docx, xlsx, pptx; позже pdf и сканы;
- таблица соответствий не шифруется — доверяем защите ноутбука (FileVault / BitLocker);
- запуск двойным кликом **или** самим Claude по просьбе пользователя (см. §8).

Юридически это псевдонимизация (обратимая замена), а не обезличивание — данные остаются персональными.

Отправная точка — скрипт `obezl.py` (практикум Struktor). Из него взяты раскладка «Сейф рядом с папкой Claude», вывод «только числа», команда проверки, распознавание столбцов xlsx по заголовкам и эксплуатационные мелочи. Детектор, фейки, склонения и работа с форматами переписаны (см. §13).

## 2. Раскладка папок

```
<рабочая папка>/
  Сейф/                        ← Claude сюда НЕ заглядывает
    Оригиналы/                   входящие файлы
    Результат/                   восстановленные результаты (с настоящими данными)
    Замены/
      zameny.sqlite              таблица соответствий (источник истины)
      zameny.csv                 её копия для просмотра в Excel, пересоздаётся при каждом запуске
    Словари/
      компании.txt               известные клиенты/контрагенты (по одному в строке)
      люди.txt                   известные люди (ФИО)
      стоп-лист.txt              что никогда не заменять
    Отчёты/                      HTML-отчёты (содержат оригиналы!)
    Обезличить / Проверить / Вернуть   (.command для macOS, .bat для Windows)
  Claude/                      ← папка проекта Claude Code
    Копии/                       обезличенные входящие
    Результат/                   сюда Claude кладёт свои результаты
    CLAUDE.md                    правила для Claude
    .claude/settings.json        запреты + хук
```

Оригиналы физически вне папки проекта Claude: чтобы их прочитать, Claude пришлось бы выйти за пределы проекта. Это сильнее запретов внутри одного проекта.

Код инструмента один на ноутбук (этот репозиторий); в рабочей папке — только данные, словари и ярлыки. Рабочих папок может быть несколько (по одной на направление/клиента), у каждой своя таблица замен.

## 3. Команды

| Команда | Что делает |
|---|---|
| `shirma init <папка>` | создаёт раскладку, ярлыки, CLAUDE.md, настройки и хук |
| `shirma obezlichit` | Оригиналы → Claude/Копии: новые файлы (и старые, если в них нашлись данные, узнанные позже) |
| `shirma proverit` | ищет в Копиях остатки данных; код выхода 1, если что-то найдено |
| `shirma vernut` | Claude/Результат → Сейф/Результат: обратная замена в содержимом и именах файлов |

Все команды печатают **только количества** — ни одного значения. Подробности (что на что заменено, где подозрения) — в HTML-отчёте в `Сейф/Отчёты/`. Ярлыки открывают отчёт в браузере; при запуске из Claude отчёт не открывается.

## 4. Обезличивание

1. Для каждого файла извлекаются текстовые фрагменты (абзац docx, строка/ячейка xlsx, строка текста) с привязкой к месту.
2. **Фаза поиска** по всем новым файлам (найденное в одном файле заменится и в других):
   - регулярки с валидацией (ИИН/БИН с контрольной суммой, IBAN KZ, карты по Луну, телефоны, email, домены);
   - организации: ОПФ + название в кавычках (ТОО, АО, ИП, ООО, ЖШС, АҚ, LLP, полные формы…);
   - люди: шаблоны «Фамилия И.О.» / «И.О. Фамилия» / ФИО с отчеством в любом падеже / казахские «ұлы/қызы» + NER Natasha;
   - xlsx и csv: столбцы по заголовкам («ФИО», «Контрагент», «БИН», «Телефон»…, кроме «Сумма», «Счёт-фактура»…) — заменяется весь столбец;
   - словари из `Сейф/Словари`, минус стоп-лист.
3. **Фаза замены** — за один проход по фрагменту (без повторной замены уже заменённого — это исключает ошибку вида `«Ромашка-02-01»`):
   - числовые данные — по «ключу» (только цифры), в формате записи оригинала;
   - имена и организации — по всем заранее сгенерированным словоформам.
4. Пишется копия в том же формате под обезличенным именем. Метаданные (автор, компания, менеджер) вычищаются; авторы примечаний и правок заменяются на «Автор».
5. Таблица замен сохраняется после каждого файла; запись через временный файл.

## 5. Фейки

| Тип | Ключ | Фейк |
|---|---|---|
| ФИО | фамилия (им. п.) + инициалы | из пула того же пола и «происхождения» (рус./каз.), все падежные формы, инициалы в обоих порядках, ВЕРХНИЙ РЕГИСТР |
| Организация | название без ОПФ и кавычек | ОПФ и кавычки сохраняются, название из пула; формы в кавычках и без |
| ИИН | 12 цифр | валидный: дата рождения сдвинута, век и пол сохранены |
| БИН | 12 цифр | валидный: дата регистрации и тип сохранены |
| Прочие 12-значные | 12 цифр | 12 цифр, первая сохранена |
| IBAN KZ | без пробелов | тот же банк (3 знака), валидные контрольные цифры, пробелы как в оригинале |
| Карта | цифры | тот же BIN банка (6 цифр), валидна по Луну |
| Телефон | последние 10 цифр | код оператора/города сохранён, формат записи как в оригинале |
| Email | целиком | локальная часть: транслит фейка человека, если адрес его; домен — транслит фейковой организации; публичные домены (gmail, mail.ru…) не меняются |
| Домен / сайт | домен | фейковый домен той же зоны |

Не заменяются: суммы, даты, прочие числа.

Правила:
- **Согласованность**: одна сущность — один фейк во всех файлах рабочей папки. «Иванов И.И.», «Ивановым Иваном Ивановичем» и «Иван Иванов» связываются по фамилии и инициалам.
- **Детерминизм**: фейк зависит от секрета рабочей папки и ключа — повторные запуски дают то же самое.
- **Редкие фейки**: пулы — редкие, но правдоподобные фамилии и имена (рус. и каз.), для организаций — экзотические растения (Кумкват, Мангостин…). Частые названия ТОО («Зенит», «Меридиан») исключены. Фейк не содержит даже части настоящей фамилии.
- **Без коллизий**: ни одна форма фейка не совпадает с формой оригинала или другого фейка. Если позже появится оригинал, совпадающий с уже выданным фейком, — предупреждение в отчёте.
- ИИН, записанный в Excel числом (ведущий 0 потерян, 11 цифр), распознаётся по заголовку столбца и дополняется до 12.

## 6. Склонения

Для каждого человека при создании генерируются все 6 падежей фамилии, имени и отчества оригинала и фейка (собственные правила для фамилий на -ов/-ев/-ин/-ский/согласную, имён, отчеств; казахские «ұлы/қызы» и женские имена на согласную не склоняются). Регистрируются связки:

`Фамилия`, `Фамилия И.О.`, `Фамилия И. О.`, `И.О. Фамилия`, `Имя Фамилия`, `Фамилия Имя`, `Фамилия Имя Отчество`, `Имя Отчество Фамилия`, `Имя Отчество` — в каждом падеже и в ВЕРХНЕМ РЕГИСТРЕ.

Поэтому обратная замена работает и для падежа, которого не было во входящих. Одиночное имя («Айгерим») не заменяется — слишком неоднозначно.

## 7. Обратная замена

- Имена и организации — по таблице форм, за один проход, длинные первыми, по границам слов.
- Числовые данные — поиск шаблонами в результате, затем по ключу: фейковый телефон в любом формате записи вернётся в оригинал в том же формате.
- Имена файлов — так же.
- Отчёт показывает, что могло не восстановиться: основы фейковых фамилий и названий, которые встретились в незнакомой форме («Петровы», «П. Петров»).
- Форматы результата: txt, md, csv, json, html и прочий текст; docx, xlsx, pptx. PDF от Claude восстановить нельзя — отчёт попросит сохранить в docx/md.

## 8. Защита от доступа Claude

1. Сейф вне папки проекта Claude.
2. `.claude/settings.json`: запрет `Read`/`Edit`/`Write` для `../Сейф/**`.
3. PreToolUse-хук: блокирует любой вызов инструмента, в аргументах которого упоминается Сейф, **кроме** трёх разрешённых команд `shirma` (их вывод — только числа).
4. CLAUDE.md: работать только в `Копии/` и `Результат/`; как попросить обезличить/вернуть.

Это снижает риск случайного доступа, но не гарантия. Основная защита — качество обезличивания, команда проверки и просмотр отчёта человеком.

## 9. Форматы

| Формат | Как |
|---|---|
| txt, md, csv и прочий текст | напрямую; кодировка utf-8 / cp1251; csv — плюс распознавание столбцов |
| docx, pptx | прямо по XML внутри архива: абзацы собираются из кусков текста, замена раскладывается обратно по кускам — форматирование сохраняется даже при разрыве слова между runs. Обрабатываются все части: тело, колонтитулы, сноски, примечания, надписи, диаграммы, правки |
| xlsx | по XML: общие строки, ячейки-числа, формулы (кэш значений сохраняется), названия листов, примечания, колонтитулы, сводные таблицы, диаграммы. Графики и форматирование не теряются (в отличие от openpyxl) |
| вложенные docx/xlsx | рекурсивно |
| картинки внутри документов | не обрабатываются — предупреждение в отчёте |
| pdf, сканы | v2 (Tesseract `rus+kaz`, результат в docx/md) |
| прочее | ошибка «формат не поддерживается», файл не копируется |

После всех точечных замен по XML-частям проходит общий «добивающий» проход: все текстовые узлы и атрибуты, которые не обработаны явно, прогоняются через замену известных сущностей.

## 10. Установка

- Python-окружение через `uv` (сам ставит нужный Python). Код — этот репозиторий.
- Ярлыки вызывают `uv run --project <путь к репозиторию> shirma <команда> --root <рабочая папка>`.
- Зависимости: natasha, pymorphy3, lxml.

## 11. Навык Claude Code (v3)

Навык управляет инструментом, но **никогда не читает Сейф**.
- `init` — разворачивает рабочую папку, проверяет установку.
- Новый формат — пишет адаптер и тест на **синтетическом** образце.
- Дообучение: пропущенный тип данных → шаблон + тест на синтетике (пользователь сам решает, что описать в чате); ложное срабатывание → правило. Словари клиентов и людей конфиденциальны — их пополняет пользователь, Claude их не видит.
- Диагностика: установка, тесты, статистика таблицы без значений.

## 12. План

**v1** (текущий)
- txt, md, csv, docx, xlsx, pptx — оба направления.
- ИИН, БИН, IBAN, карты, телефоны, email, домены; ФИО (рус. + каз., все падежи); организации; словари и стоп-лист; столбцы по заголовкам.
- SQLite + выгрузка в csv; HTML-отчёты; `proverit`; ярлыки macOS/Windows; хук и настройки.

**v2**: pdf и сканы (OCR), адреса, удостоверения/паспорта, номера договоров, шаблоны из `config/`.

**v3**: навык; кнопка «добавить в словарь / стоп-лист» из отчёта.

## 13. Отличия от `obezl.py`

| | obezl.py | здесь |
|---|---|---|
| Фейки | коды `Условный А. Б.`, `000000000001` | реалистичные, валидные |
| Склонения | нет: «Ивановым Иваном Ивановичем» утекает, «Иванову И.И.» и «Иванов И.И.» — два разных человека | все падежи, одна сущность |
| Казахские буквы | нет в шаблонах | есть |
| Имя без отчества/инициалов | не ловится | NER Natasha |
| «И.О. Фамилия» | не ловится | ловится |
| Замена | последовательные `replace` → повторная замена внутри кода | один проход |
| docx | только тело и таблицы, форматирование абзаца теряется | все части, форматирование сохраняется |
| xlsx | openpyxl: теряются графики, названия листов и примечания не обрабатываются, ИИН с ведущим нулём-числом утекает | по XML |
| Телефон в разной записи | разные коды | один ключ |

## 14. Известные риски

- Пропуски детектора — главный риск. Снижается словарями, проверкой и просмотром отчёта.
- Claude может перефразировать фейк («Пётр» вместо «П. Петров») — не восстановится автоматически; отчёт восстановления подсвечивает подозрительное.
- Производные факты: возраст по фейковому ИИН будет другим.
- Коллизия реального человека с ранее выданным фейком — предупреждение в отчёте.
- Казахская морфология и NER для казахских имён — неполное покрытие.
